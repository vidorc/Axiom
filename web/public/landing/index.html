Why Axiom

An engine, not a toy canvas.

The workflow that matters is the one that finishes. Axiom is built around durability, your credentials, and composability — the three things automation tools get wrong.

Durable by default.

Kill the process mid-run and it resumes to exactly-once completion. An append-only event log and lease-based recovery mean no double-sends — ever.

Bring your own keys.

Credentials are sealed with envelope encryption and unwrapped in memory only. Plaintext never lands in a log, an event, or a database row.

Composable nodes.

Wrap any provider as an HTTP manifest in minutes, or drop to code when you need it. Compose them into a DAG with parallel branches and typed retries.

The orchestrator

A compute model for go-to-market.

Postgres and Redis under the hood — no Temporal, no black box. You define the workflow declaratively; Axiom claims, runs, settles, and reaps every node with sub-100 ms orchestration overhead.

  • ✓ Parallel branches with per-node retry policy and a strict error taxonomy.
  • ✓ Crash recovery proven under kill -9 — verified in CI.
  • ✓ A real cost ledger: per-node, per-token spend rolled up per run.
